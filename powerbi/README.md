# ASG Airlines — Power BI Dashboard

## 1. Dashboard Overview

The ASG Airlines Power BI dashboard provides an operational view of flight activity, booking patterns, flight duration, route traffic, and overnight-flight behavior.

The dashboard is built on the cleaned and transformed Gold-layer datasets produced by the Python data engineering pipeline.

The report contains four analytical pages:

1. **Executive Overview**
2. **Duration & Anomaly Analysis**
3. **Route Performance**
4. **Overnight Route Analysis**

The dashboard is designed to support operational analysis while making data-quality issues and analytical limitations visible to the user.

# 5. Flight Duration Logic

Flight duration is calculated from departure and arrival timestamps.

For normal same-day flights:

```text
arrival_time - departure_time
```

For overnight flights, when the arrival time is earlier than the departure time, the arrival timestamp is interpreted as occurring on the following day.

Conceptually:

```text
if arrival < departure:
    arrival = arrival + 1 day
```

This prevents valid overnight flights from producing negative durations.

Example:

```text
Departure: 20-Apr 23:38
Arrival:   21-Apr 02:32

Duration: approximately 2 hours 54 minutes
```

---

# 6. Temporal Anomaly Handling

Not every arrival-before-departure record is assumed to be an overnight flight.

The pipeline evaluates the timestamps and applies the defined business rules.

Records that cannot be resolved reliably are quarantined instead of being silently corrected.

The dashboard currently highlights:

**1 temporal anomaly quarantined**

This prevents an invalid record from distorting flight-duration analysis.

# 8. Payment Interpretation

The dashboard includes payment-related metrics such as:

- Valid Payment Transactions
- Total Payment Value
- Invalid Payment Transactions

The total payment value is **not treated as revenue**.

The source payment data contains multiple payment rows for some bookings and does not provide sufficient payment-status information to reliably distinguish successful payments from retries, refunds, or partial transactions.

Therefore:

> Total Payment Value represents the value of valid payment records processed by the pipeline and should not be interpreted as recognized airline revenue.

---

# 9. Delay Analysis Limitation

The source dataset does not contain separate scheduled and actual departure/arrival timestamps.

Therefore, conventional airline delay KPIs such as:

- Average Departure Delay
- Average Arrival Delay
- On-Time Performance
- OTP %
- Delay Minutes

cannot be calculated reliably.

Instead, the dashboard focuses on:

- Flight duration
- Overnight operations
- Temporal anomalies
- Route traffic
- Airline flight volume
- Booking status

This avoids inventing delay information that is not present in the source data.

# 14. Relationship to the Data Engineering Pipeline

Power BI does not perform the primary data-cleaning logic.

The Python pipeline is responsible for:

- Data ingestion
- Standardization
- Timestamp parsing
- Duration calculation
- Overnight-flight handling
- Anomaly detection
- Quarantine processing
- Referential-integrity checks
- Gold-layer generation
- KPI generation

Power BI consumes the resulting analytical outputs for reporting and exploration.

This separation keeps transformation logic reproducible and makes the BI layer easier to maintain.

# 16. Limitations

The dashboard should be interpreted within the limitations of the supplied dataset.

1. Scheduled and actual timestamps are not available, so conventional delay metrics cannot be calculated.
2. Payment records do not provide sufficient information to classify total payment value as airline revenue.
3. Airline values contain missing and UNKNOWN records.
4. One temporal anomaly is quarantined rather than automatically corrected.
5. Route-level analysis depends on the cleaned and validated flight records.
6. Booking status data contains invalid/null values that require separate interpretation.

## 18. Conclusion

The Power BI dashboard provides the reporting layer for the ASG Airlines end-to-end data engineering case study.

Rather than presenting only static KPIs, the report connects operational metrics with data-quality indicators and route-level analysis.

The resulting dashboard allows users to quickly answer questions such as:

- How many valid flights are available?
- Which airlines have the highest flight volume?
- What is the typical flight duration?
- How many flights operate overnight?
- Which routes have the highest traffic?
- Which routes have longer average durations?
- Which routes have a higher overnight-flight percentage?
- What data-quality issues need operational attention?

The dashboard therefore complements the Python-based ingestion, cleaning, validation, quarantine, and Gold-layer transformation pipeline.
